1. Introduction
1.1 Purpose
This Software Requirements Specification (SRS) defines the complete set of requirements for ProjectMarket DBU — a web-based academic project management platform for Debre Berhan University. It serves as the primary reference for developers, testers, stakeholders, and university administrators involved in the system's design, implementation, and evaluation.
1.2 Scope
ProjectMarket DBU covers the following functional scope:
User registration, authentication, and role management
Project idea submission, browsing, and lifecycle management
Student team formation, membership, and approval workflows
Supervisor (instructor) selection and assignment
Weekly progress reporting with file attachments
Real-time notifications and team communication (chat)
Role-specific dashboards for students, instructors, departments, and admins
Out of scope for this version:
Video conferencing or external meeting integration
Automated grading or academic scoring
Integration with external LMS platforms (e.g. Moodle)

2. Overall System Description
2.1 Product Perspective
ProjectMarket DBU is a standalone web application with no dependency on existing DBU software systems. It will be accessible via modern web browsers on desktop and mobile devices. The system interfaces with three external services:
Cloudinary — for file and document storage
Email Service (SMTP) — for notifications and password resets
PostgreSQL (Neon) — hosted relational database
2.2 Product Functions
The platform delivers the following high-level functions:

2.4 Operating Environment
Web Browsers: Chrome 100+, Firefox 100+, Edge 100+, Safari 15+
Frontend: React 18+ served via Vercel CDN
Backend: Node.js 18+ on Render (Linux container)
Database: PostgreSQL 15 on Neon serverless
Network: Requires stable internet (minimum 1 Mbps for file uploads)
2.5 Design and Implementation Constraints
Must use REST API architecture (no GraphQL in v1)
All data must be stored in PostgreSQL — no NoSQL databases
JWT tokens must not exceed 24-hour validity
File uploads must be routed through Cloudinary — no local disk storage
All API communication must occur over HTTPS

5. System Constraints
5.1 Technical Constraints
The system must be built using the approved tech stack: React, Node.js/Express, PostgreSQL, Prisma, Socket.IO
Deployment is restricted to Vercel (frontend), Render (backend), and Neon (database)
File storage must use Cloudinary; no local disk storage is permitted in production
The system must function without requiring browser plugins or extensions
5.2 Business Constraints
The platform must be usable without any paid subscriptions for core academic use
Industry partners must be approved by an admin before accessing the platform
Student data must comply with DBU's data privacy policy
5.3 Regulatory Constraints
User data must be handled in compliance with applicable data protection laws
Passwords must never be stored in plaintext
Audit logs of admin actions must be retained for a minimum of 90 days
6. Assumptions and Dependencies
6.1 Assumptions
All DBU students have a valid university email address for registration
Users have access to a modern web browser and stable internet connection
Instructors voluntarily participate in the supervisor selection process
Industry partners are pre-vetted and approved by DBU administration
Students are responsible for forming their own teams; the system facilitates, not mandates
